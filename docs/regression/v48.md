## Analyse de risque de régression

Le changement touche `.hdr`/`.logo`/`.nav`/`.nav-b`/`#settings-btn` dans `style.css`, uniquement à l'intérieur d'une media query `max-width:700px`. Ces classes sont utilisées sur **tous les écrans** (le header est commun), donc le rayon d'impact potentiel est large en surface, mais la modification elle-même est étroite (uniquement sous 700px de large, uniquement des propriétés d'affichage/taille, aucun changement de structure HTML ni de logique JS).

- **Navigation elle-même** (la feature directement modifiée) : re-testée sur les 3 largeurs (iPhone portrait, iPhone paysage, iPad) — voir QA-18. PASSED.

- **Écran Match iPad** : non re-capturé dans cette passe (le fix ne touche aucune classe spécifique à `.match-layout`) — risque jugé négligeable, pas de re-test complet exigé pour un changement aussi ciblé.

## Ce qui n'a pas été retesté en profondeur (test de fumée, pas de raison de suspicion)

- Saisie d'action, alertes automatiques, stats GB, export PDF, import/export CSV : aucune de ces zones de code n'est touchée par le diff (`app.js` non modifié). Pas re-testées dans ce cycle — cohérent avec le mandat du Regression Guardian de ne pas tout re-tester en profondeur à chaque changement, seulement ce qui est plausiblement impacté.
