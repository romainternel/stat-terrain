# Risques — Grille DC sur le terrain + Raccourcis en-tête

| # | Risque | Probabilité | Impact | Recommandation |
|---|---|---|---|---|
| R1 | **F1** — Un coach qui ajoute manuellement des joueurs DC au-delà des 5 réels (CSV, "+ Ajouter") dépasse le layout dédié à 5 et retombe sur le fallback générique "2 par rangée" (3 rangées pour 6, jamais testé à cette position resserrée) — pourrait recommencer à chevaucher légèrement. | Faible (le roster réel plafonne à 5, un ajout manuel au-delà est un cas d'usage marginal) | Faible (dégradation progressive, pas un retour au bug initial à l'identique) | P3 — pas d'action requise pour cette itération, à revisiter seulement si Romain remonte un cas réel à 6+ |
| R2 | **F1** — Le nouveau layout à 5 partage le même bloc de code (`layouts` dans `courtPlayerPositions()`) que les layouts 2/3/4 déjà utilisés par PVT — une erreur de frappe en ajoutant l'entrée `5` pourrait casser silencieusement 2/3/4 aussi (régression PVT). | Faible (modification additive, pas de ligne existante touchée) | Moyen si ça arrivait (PVT est un poste réel avec 3 joueurs, déjà testé/validé STORY-38) | P1 — critère d'acceptation explicite : re-tester PVT à 3 et 4 joueurs après le changement, pas seulement DC, pour confirmer l'absence de régression croisée sur le code partagé |
| R3 | **F2** — Le changement de structure flex de l'en-tête (déplacement de `margin-left:auto` de `#settings-btn` vers `.hdr-shortcuts`) est le point le plus fragile de cette story : mal fait, l'espacement entre logo/raccourcis/réglages/nav peut se retrouver visuellement cassé (éléments collés ou au contraire trop espacés), potentiellement seulement visible sur certains écrans (avec vs sans `#settings-btn` visible). | Moyenne (erreur classique avec les marges automatiques flex multiples) | Moyen (dégradation visuelle de l'en-tête, visible sur toute l'app, mais rien de fonctionnellement cassé — les boutons restent cliquables) | P1 — critère d'acceptation explicite : vérifier visuellement l'en-tête sur un écran SANS match actif (logo + raccourcis + nav) ET sur un écran AVEC match actif (logo + raccourcis + Réglages + nav), aux largeurs desktop/tablette et iPhone étroit |
| R4 | **F2** — Le raccourci Suivi GB n'a pas de confirmation (comportement hérité des 2 sites existants, volontairement conservé) ; un 3e point d'accès plus visible dans l'en-tête augmente la probabilité d'un tap accidentel qui coupe le suivi GB en plein match sans que le coach s'en rende compte immédiatement. | Moyenne (accès plus facile = plus de taps, y compris accidentels) | Faible (juste re-basculer suffit à corriger, aucune perte de données — seule la capture de zone d'impact au prochain tir est affectée, pas les événements déjà enregistrés) | P2 — pas de nouvelle confirmation à ajouter (romprait la cohérence avec les 2 sites existants et l'esprit "raccourci rapide" demandé), mais le Designer a déjà prévu un indicateur visuel d'état permanent (couleur ON/OFF) — suffisant pour qu'un coup d'œil confirme l'état |
| R5 | **F2** — Basculer Mode Expert→Simple depuis l'en-tête pendant qu'on consulte un autre écran (Stats, Bilan) déclenche la confirmation bloquante existante par-dessus cet écran, potentiellement déroutant hors du contexte Match où on s'y attend habituellement. | Faible | Faible (juste une confirmation à lire, comportement de sécurité voulu, pas une perte de données) | P3 — comportement hérité et volontairement conservé par le PRD, pas une nouvelle mitigation à construire |

## Synthèse priorités
- **P1** : R2 (re-tester PVT après le changement partagé), R3 (vérification visuelle de l'en-tête dans les 2 états, 2 largeurs).
- **P2** : R4 (déjà mitigé par l'indicateur visuel prévu au Design).
- **P3** : R1, R5 — aucune action requise pour cette itération.
